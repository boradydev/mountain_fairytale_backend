## Правила приёмки

- Результат ручной проверки отдельно от автоматического PASS API/SQL.
- Состояния: PASS, FAIL, BLOCKED; N/A — только с явным решением владельца.
- Использовать существующие контрольные CORE-документы только для чтения;
  изменения — только новых QA-объектов/MANUAL и после согласования сценария.
- Не удалять или сбрасывать постоянную QA, не изменять seed-манифест и
  журнал `.codex-tmp/qa-scenarios/` из этапа 3.
- Не повторять без причины уже пройденные независимые проверки финансовых
  строк и сохранённых начислений этапов 2–3.
- Дефект: фактическое/ожидаемое → согласовать изменение → регрессия → повтор.
- Задания Codex и изменения бизнес-логики — только после согласования требований.
