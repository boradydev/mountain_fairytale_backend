# QA-сценарии для Flutter + автоматической сверки

Главная стратегия: [../README.md](../README.md).

На этапе 3 создаём сценарии вида `QA-001-<slug>.md`.
Каждый сценарий описывает:
- Идентификатор и цель; подготовленное начальное состояние (seed-набор).
- Какие действия выполняет **человек в реальном Flutter Windows**, шаг за шагом.
- Какие значения и признаки человек проверяет визуально (включая PDF).
- Какая команда проверяющего запускается после действий.
- Ожидаемые значения, независимые формулы для сумм и комиссий, а также
  инварианты БД/API и журнала аудита.
- Порядок повторного запуска и очистки **только своего QA-набора**.
- Критерии PASS/FAIL, идентификаторы проверенных объектов и ссылки на отчёт.

Отчёт проверки не должен объявлять UI/PDF пройденными, если автоматом
проверена только база данных. Визуальные проверки требуют отметки владельца.

**Сценарии ещё не созданы: их входные данные и способы сверки определим на
этапах 2–3.**
