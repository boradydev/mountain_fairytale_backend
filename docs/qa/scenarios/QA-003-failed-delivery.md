# QA-003 — неудачная доставка

Нужен PASS QA-002. Использовать тот же UUID маршрута от **08.11.2026**.

```powershell
.\scripts\qa\qa.ps1 scenario-prepare QA-003
```

1. Открыть выданный маршрут во Flutter, нажать **Редактировать**.
2. У **QA-MANUAL-21** выбрать **«Не доставлено»**, причина строго
   **`QA-003: клиент отказался`**.
3. Не менять строки: Товар-1 **3 × 20,00**, Товар-8 **1 × 19,90**.
   Вторая точка остаётся доставленной, Товар-2 **3 × 30,00**.
4. Визуально проверить статус/причину, сохранность товаров и собственной
   суммы первой точки **79,90**. Учитываемая сумма маршрута **90,00 ₽**.
5. Сохранить, дождаться успеха, повторно открыть. Проверить статус, причину
   и суммы. Открыть печать/PDF маршрута: товарная сводка загрузки должна
   сохранять Товар-1 **3 шт.** недоставленной точки и Товар-2 **3 шт.** второй;
   свободный Товар-8 в сводку обычных товаров не включается.
6. Открыть клиента 21 / последний успешный заказ: текущая недоставленная
   точка не должна подменять предыдущий успешный заказ. Если прежних успешных
   заказов нет, результат может быть пустым.

```powershell
.\scripts\qa\qa.ps1 scenario-verify QA-003
```

PASS подтверждает сохранность UUID/строк/снимков/ставок, нулевой оборот
и комиссию представителя первой точки, маршрут **90,00**, точную комиссию
employee0 **1.125**, аудит, latest-order и исходные количества для загрузки.
PDF и видимость статусов подтверждает человек. FAIL: сохранить диагностику
и наблюдения, не удалять документ, не исправлять SQL. Сетевой сбой — повторить
verify. Проверки QA-001/002 после этого шага дают историческое подтверждение,
а не PASS текущего изменённого состояния.
