# QA-001 — создать маршрут

Подготовка: управляемый QA API `http://127.0.0.1:8001`, Flutter подключён
именно к нему, вход qa_admin. Открыть backend PowerShell и выполнить:

```powershell
.\scripts\qa\qa.ps1 scenario-prepare QA-001
```

Дождаться READY. Команда выдаст уникальную памятку, имена/UUID справочников,
способы оплаты и актуальный начальный пробег. При отказе остановиться;
справочники для обхода отказа не менять.

1. Во Flutter открыть календарь доставок, выбрать **08.11.2026**, создание
   документа → **Доставка / маршрутный лист**.
2. В «Данные рейса» выбрать выданные командой QA-водителя и QA-автомобиль
   (обычно Водитель-0, Автомобиль-0, А900АА99). Начальный пробег — строго из
   подготовки, конечный оставить пустым.
3. Первым добавить **QA-MANUAL-21-Не-доставлено** и открыть меню этой точки
   → **«Добавить памятку»**. В PowerShell в выводе подготовки найти поле
   **`memo` у первой точки**. Скопировать его значение **целиком, без внешних
   кавычек**: текст `QA-001 run=` и все 36 символов UUID после знака `=`
   (вместе с дефисами). Вставить эту строку в памятку и подтвердить ввод.
   Нужен UUID **запуска сценария**, а не UUID маршрута, клиента или цикла.
   **Многоточие вводить нельзя: в памятке должен быть настоящий полный UUID.**
   Перед сохранением сверить памятку с полем `memo` посимвольно.

   Если вывод подготовки уже закрыт, показать ту же строку повторно:

   ```powershell
   .\scripts\qa\qa.ps1 scenario-status QA-001
   ```

   Эта команда читает существующую подготовку; заново выполнять `prepare`
   для получения памятки не нужно. После `-NewCycle` брать строку только
   из нового активного запуска — памятка прежнего цикла не подойдёт.
4. Добавить Товар-1: количество **2**, цена **20,00**. Добавить Товар-8 со
   свободной ценой: количество **1**, цена **12,50**, уточнение
   **`QA-001: тест свободной цены`**. Визуально проверить строки 40,00 и 12,50,
   сумма точки **52,50**. Оставить проверенный подготовкой способ оплаты
   (исходно QA-MANUAL-Наличные); не менять карточку клиента.
5. Вторым добавить **QA-MANUAL-22-История**. Товар-2: количество **3**,
   цена **30,00**, сумма **90,00**. Способ оплаты — из подготовки
   (исходно QA-MANUAL-Карта).
6. Проверить порядок 21 → 22, три строки, отметки «Доставлено», дату и итог
   **142,50 ₽**. Нажать **Сохранить** один раз, дождаться успеха.
7. Снова открыть сохранённый маршрут через документы дня/историю. Визуально
   проверить памятку, оплату, уточнение, количество и цены, общий итог.
8. В PowerShell выполнить:

```powershell
.\scripts\qa\qa.ps1 scenario-verify QA-001
.\scripts\qa\qa.ps1 scenario-status
```

PASS означает, что API/SQL, суммы, точные комиссии (rep0 **3.9375**,
employee0 **1.78125**), идентичность, аудит и CORE прошли сверку.
Визуальный результат сообщить отдельно. При FAIL сохранить диагностику,
UUID и наблюдения; не создавать второй маршрут и не удалять первый.
Сетевой сбой допускает повтор verify. Не повторять prepare для этого запуска;
его инструкцию можно прочитать `scenario-status QA-001`.
QA-002 готовить только после PASS.
