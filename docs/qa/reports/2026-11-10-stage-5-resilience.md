## Среда и границы

Исходные рабочие деревья чистые, оба репозитория на `codex/delivery-history`;
backend `5a497b5`. Пользовательский Flutter Windows debug обнаружен и не
останавливался. Общие API не запускались и не завершались. Production-код,
SQL, миграции, финансы, сохранение, блокировки и Dashboard не менялись.

`tests/run_resilience.py` создаёт две уникальные базы
`mf_resilience_{api|repo}_{uuid}_test` на локальном PostgreSQL. Проверяет
отсутствие имени до CREATE, фактическое имя после подключения, сохраняет OID.
Штатные pytest-фикстуры применяют Alembic до head и пересоздают только эти
тестовые схемы. Локаль Windows — `Russian_Russia.utf8`, UTF8. Перед DROP
проверяются UUID имени, исходный OID и отсутствие подключений. Чужие соединения
не завершаются, защитные маркеры не отключаются. Базы удаляются в finally.

Стенд использует настоящий FastAPI/uvicorn в отдельном Python-процессе,
динамически выбранный localhost-порт и asyncio TCP-прокси на другом порту.
Каждая native-фикстура запускает свой API; остановка выполняется только через
сохранённый `Popen`, без поиска/завершения чужих PID. Логи API сохраняются в
pytest basetemp. Подготовка сотрудников, клиентов, автомобиля, водителя, товара,
маршрута/самовывоза переиспользует существующие PostgreSQL/API-фикстуры с
ASGITransport; аварийные запросы и восстановление идут через настоящий TCP.
Во всех случаях есть независимый SQLAlchemy-сеанс для проверки PostgreSQL.
В финальном аварийном наборе первый сотрудник имеет комиссию 7,5%, второй также
авторизуется независимо. PATCH меняет количество на 3, цену на 13,25 и, для
маршрута, конечный пробег на 115. Ожидаемый оборот — 39,75, при создании — 25.

## Момент сбоя и независимая сверка

Прокси поддерживает pass/offline/partial/lost/delay. При partial сервер получает
полный Content-Length, но только половину JSON, затем TCP закрывается. При lost
полученный HTTP-ответ удерживается внутри прокси; тест сначала видит новую строку
или operationId/revision отдельным PostgreSQL-сеансом и только затем разрешает
прокси закрыть клиентское соединение. Сетевая ошибка не служит доказательством
rollback. После восстановления POST ищется через creation-requests, PATCH через GET.

В `tests/resilience_server.py` только дочерний тестовый процесс оборачивает
`DeliveryDocumentsUOW.commit`. При наличии уникального gate-файла он пишет аудит,
выполняет flush и подтверждает достижение точки отдельным marker-файлом; COMMIT
ещё не вызван. Контроллер проверяет неизменность видимого снимка и снимает gate
для исключения либо завершает принадлежащий ему процесс. Это единственная
подмена записи backend; финансовые функции, репозитории и PostgreSQL настоящие.
Для long poll тестовый child также оборачивает DashboardChanges.wait:
при актуальных serverId/version и timeout > 0 пишет marker и вызывает исходный
метод без изменения параметров/правил. Контроллер видит marker и незавершённый
HTTP-запрос, проверяет отсутствие транзакции в БД, затем останавливает свой API.

SQL-снимок содержит все public-таблицы: документы, точки, товары, creationRequestId,
revision/lastOperationId, комиссии, lock, события/actor_id, машину и пробег.
До/после несостоявшейся записи снимки равны. После потерянного ответа и повторного
POST снимки также равны уже подтверждённому COMMIT: новые дубликаты и события
отсутствуют. Проверяются прирост числа документов/точек/товаров 1/2/1 для POST,
0/0/0 для PATCH, revision 1/2, актор и арифметика Decimal комиссий/оборота.
После случаев проверяется отсутствие чужих открытых транзакций и ожиданий Lock.
Истечение lock моделируется изменением expires_at только своей test-БД с SELECT
после COMMIT; ожидание реальных 120 секунд не требуется.

При одновременных устаревшей ревизии и чужом lock действующий backend сначала
проверяет revision и возвращает 409 с currentRevision; 423 ожидается для
актуальной ревизии. Первоначальное ожидание теста 423 исправлено по коду
`UpdateDeliveryDocumentUseCase.execute`, production-поведение не менялось.

## Ограничения и ручные действия

Нативный Flutter Windows E2E с этим proxy не выполнялся: существующие live-тесты
не управляют авариями сохранения, а текущий пользовательский debug не
перенастраивался. Widget/provider-матрица и native HTTP/БД проверены раздельно.
Физическая сеть Windows и системные службы не трогались. Нет доказательства
поведения при падении самого PostgreSQL, ОС или выключении питания.
Перезапуск API во время открытого long poll и смена serverId проверены реальным
HTTP с тестовым marker входа в ожидание. Правила Dashboard сохранены.
Обязательных ручных действий для завершения автоматического блока нет;
необязателен native Flutter smoke с потерей связи на отдельно настроенном стенде.
Владельцу остаётся оценить отчёт и принять блок; весь этап 5 автоматически не принят.

учётная запись разработки. При отсутствии локального .venv зависимости не устанавливать.
