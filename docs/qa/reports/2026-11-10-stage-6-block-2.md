## Расхождения при выполнении и их причины

1. Первоначально API был только на internal bridge. Docker Desktop не пропускал
   host HTTP к опубликованному порту. Созданы отдельные собственные ingress bridge;
   PG остался только во внутренней сети. HTTP стал доступен только через
   `127.0.0.1`; после этого все API-проверки прошли. Это конфигурация стенда,
   production-Compose не редактировался.
2. Первичный assert временного проверяющего ожидал ошибочную комиссию `27.77`.
   После чтения точного SQL-снимка и контракта проверяющий исправлен на независимую
   Decimal-формулу и `27.77625`. Fixture дочитан из уже созданных объектов;
   повторного seed и дублирующих документов не было. Production-дефекта нет.
3. После успешного restore strict raw schema hash отличался только у
   `delivery_documents_document_type_check`. PostgreSQL deparser переписал cast
   массива в casts его элементов:

   ```sql
   -- Исходное выражение ANY:
   (ARRAY['delivery_route_sheet'::varchar, 'pickup_sheet'::varchar])::text[]
   -- После pg_dump/pg_restore:
   ARRAY[('delivery_route_sheet'::varchar)::text, ('pickup_sheet'::varchar)::text]
   ```

   Оба выражения сравнивают `document_type::text` с одинаковыми двумя константами.
   На обоих кластерах дополнительно проверены 8 входов, включая NULL, обе
   допустимые строки, пустую/неизвестную/другой регистр/кириллицу/пробел:
   результат `IS NOT DISTINCT FROM` везде true. Нормализована **только точная
   пара известных определений данного именованного constraint**; остальные
   58 constraints проверены без послаблений. Raw snapshots сохранены отдельно;
   raw hashes source/restore:
   `ddda21e4cb0129340b7ac80ebca63425a9997901bc5090d88d12ccadab75a711` /
   `e89c728aa46a155b26bd7d35e27e94ba6cbf8a884aa5094af1640c718dbadb36`.
   После доказанной нормализации schema hash совпал. Данные не менялись,
   повторный restore и Alembic на восстановленной БД не выполнялись.
4. Один вспомогательный stdin metadata probe имел SyntaxError; исправленный
   probe прошёл без каких-либо DB-операций. Git status сообщает о недоступной
   старой `.tmp/pytest-cache/`; права/содержимое этого чужого каталога не менялись.

Неразрешённых FAIL и новых дефектов production-кода в объёме 6.2 не обнаружено.
