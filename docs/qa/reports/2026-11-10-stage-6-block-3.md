## Исправление S6-01

Раньше `UpdateService.latest()` преобразовывал HTTP не-200 в FormatException,
а `UpdateProvider.check()` показывал один текст «Проверьте подключение к интернету»
для HTTP, повреждённого JSON, таймаута и транспортных ошибок.

Минимальное изменение:

- `UpdateHttpException(statusCode)` сохраняет HTTP-код; HTTP отказ теперь
  показывается как `HTTP NNN` с пояснением для 403, 429, 5xx.
- FormatException от UTF-8/JSON/schema/размера означает повреждённое описание.
- TimeoutException получает отдельный текст о времени ожидания.
- Socket/HTTP client/HTTP transport/TLS exceptions относятся к соединению;
  неожиданные исключения получают нейтральный текст, без утверждения «нет интернета».
- 404 остаётся нормальным отсутствием первого релиза. Повтор очищает прошлую
  ошибку; пассивная проверка не запускает native updater.

Не менялись signature verification, native bridge, callbacks, installer,
production feed allowlist, совместимость/auth/формы и правила работы с токенами.
Используются прежние UI и ConfirmDialog/AppIconButton; новые widgets не создавались.
Flutter-инструкция дополнена описанием разных диагностик.

## Оставшееся ограничение native N6-01 — диагностика WinSparkle

Два отдельно воспроизведённых случая в настоящем WinSparkle:

- Намеренный обрыв корректно подписанной загрузки после 1 МБ дал «Приложение
  неправильно подписано», как и действительно чужая подпись. Неполный файл
  безопасно отвергнут, A не изменилась, повтор доступен.
- Исправный `update.json`, затем **HTTP 503 именно на XML appcast**: WinSparkle
  показал «При поиске обновления произошла ошибка. Проверьте подключение к
  интернету и попробуйте ещё раз» (сообщение подтверждено владельцем).
  HTTP-сервер доступен и намеренно отвечает 503; это не доказательство
  отсутствия сети. B не заменена.

Это оставшееся ограничение **нативной диагностики**, отдельное от устранённого
Dart S6-01. WinSparkle самостоятельно получает XML/installer и показывает свои
окна. Обработчик/DLL не модифицировались; изменение vendor/native диагностики
или preflight этого второго HTTP-пути требует отдельной задачи и оценки.
Проверка подписи и production allowlist не ослаблялись.

## Исторический v1.1.2 → v1.2.0

`git diff v1.1.2 v1.2.0 -- lib/features/app_updates windows/runner/update_bridge.cpp
scripts/windows/prepare_release.py windows/installer/app.iss` — различий нет.
Старый Dart код действительно объединял HTTP/format/network в один текст;
S6-01 воспроизводится и устранён. Старый native bridge уже передавал полную
`major.minor.patch.build`, feed формировался с той же четырёхкомпонентной версией.
Регрессия `1.1.2+65535 → 1.2.0+20` PASS, версия сравнивается семантически.

Нынешний native HTTP 503 действительно воспроизводит совет «проверьте интернет»;
поэтому старый симптом может относиться и ко второму HTTP-пути WinSparkle.
Это гипотеза о старом инциденте: нет доказательства, какой диалог/HTTP-ответ
был у владельца тогда. Точный старый EXE/installer/feed/key/network trace не
воспроизведён. Локальные старые acceptance packages имели версии 1.0.0/1.0.1,
их не приняли за требуемые артефакты 1.1.2/1.2.0. Production feed не запрашивался
ради реконструкции. Успех нынешнего Debug A→B не означает PASS именно старого
перехода. **Историческая первопричина остаётся неустановленной.**

## Решение владельца — 10.11.2026

**Блок 6.3 принят** по результатам реальных WinSparkle/Inno A→B,
негативных сценариев и исправления S6-01. Оставшееся N6-01 — качество
сообщений самого WinSparkle при HTTP 503 и обрыве файла — признано
неблокирующим для следующего блока, поскольку повреждённая установка
не применяется и повтор доступен. Непроверенная native авторизованная сессия,
непроверенный обычный Release HTTPS updater и неизвестная историческая
первопричина остаются явными ограничениями. Их нельзя обозначать PASS.
Владелец разрешил [финальный блок 6.4](../stages/06-4-final-release-readiness.md);
это не разрешение на выпуск, merge в master или обновление рабочей VM.
