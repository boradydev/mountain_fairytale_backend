## BUG-001 — исправление 07.11.2026

подтверждал повторную проверку, дефект не закрыт. Этап 3 не начат.

Текстовая ветка всегда ищет полную исходную строку после strip; пустой запрос,
экранирование метасимволов и SQL-параметризация сохраняются.

### Генератор телефонов

`tests/helpers.py::unique_phone()` выдаёт `+79` и девять ASCII-цифр, всего 11 цифр.
Случайное начальное смещение выбирается один раз в процессе; далее счётчик
преобразуется как `(offset + index * 618033989) % 1000000000`.
Шаг взаимно прост с размером диапазона, поэтому это перестановка миллиарда
значений без повторов. После исчерпания диапазона — явный отказ, без коллизий.
Lock защищает выдачу из нескольких потоков. PostgreSQL и сторонние библиотеки
для генерации не используются.

Разнесение счётчика по диапазону сохраняет смысл тестов поиска возможных дублей:
обычный последовательный счётчик создавал слишком похожие соседние номера и
коллизии с номерами, специально изменёнными на одну цифру. Это выявлено в
совместной проверке `test_check_duplicate_scenarios` / `test_duplicate_score_ranking`;
их assertions не менялись, дефекта приложения не обнаружено.

Номера синтетические, используются только в тестовых записях, без звонков/SMS.

### Изоляция обзвона и порта

Короткие телефонные запросы могут находить записи любых предыдущих тестов.
Тест собирает все страницы по 25, проверяет стабильный total, точные offset/limit,
размер каждой страницы, отсутствие дубликатов и соответствие числа записей total.
Затем проверяет исходное множество своих клиентов. Поиск по уникальной текстовой
метке по-прежнему должен давать ровно три записи; отдельная проверка offset=1,
limit=1 сохранена и усилена проверками метаданных.

Добавлены 26 посторонних совпадений с именами, сортирующимися перед QA-клиентами:
тест воспроизводит выход нужных клиентов за первую страницу даже отдельно.
Их имена не содержат текстовую метку основной тройки. Чужие записи не удаляются,
лимит не увеличен, сортировка и критерии обзвона не менялись.

Временный инфраструктурный тест monkeypatch-ит только свою `qa.API_PORT` в 0.
Существующий `with socket.socket()` выполняет bind(127.0.0.1, 0), ядро выделяет
порт, после проверки сокет штатно закрывается. HTTP-сервер этот тест не запускает,
выбранный номер затем не переиспользуется, поэтому гонки «проверить порт — позже
занять тот же порт» здесь нет. Для будущего теста настоящего сервера потребуется
удерживать сокет до передачи серверу, а не использовать эту проверку как резерв.
Все проверки БД/роли/маркера/Alembic и cleanup временных ресурсов сохранены.
Настройки постоянного QA API и `.env.qa` не менялись.
