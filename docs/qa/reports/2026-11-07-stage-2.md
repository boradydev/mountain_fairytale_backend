## Выявленный дефект при ручной приёмке (07.11.2026)

**BUG-001 — буквенно-цифровой поиск ошибочно включает поиск по телефону.**
При запросе `QA-CORE-00` появляются разные клиенты: backend дополнительно
извлекает `00` из строки и ищет эту подстроку в `QA-TEST-00xx`.
При `QA-CORE-01` аналогично находятся не относящиеся к текстовому запросу
клиенты. Причина подтверждена чтением SQL/репозитория; она есть также в
списке клиентов и legacy-поиске истории. Это дефект поисковой семантики,
**не дефект CORE/MANUAL seed**. По отдельному заданию владельца выполнено
исправление ниже; этап 2 остаётся «На проверке».


## BUG-001 — исправление 07.11.2026

Статус: **Исправлен, ожидает ручной проверки Flutter**. Владелец ещё не
подтверждал повторную проверку, дефект не закрыт. Этап 3 не начат.

Причина: из смешанного текста извлекались цифры, после чего OR-ветка телефона
находила посторонних клиентов. Теперь `extract_phone_search_digits` возвращает
цифры только для запроса телефонного формата после strip: хотя бы одна
ASCII-цифра `0–9`, остальные символы — только обычный пробел, `+`, `-`, `(`, `)`, `.`.
Для текста/других символов возвращается пустая строка. Минимальной длины нет.
Текстовая ветка всегда ищет полную исходную строку после strip; пустой запрос,
экранирование метасимволов и SQL-параметризация сохраняются.

Исправлены три пути: история клиентов, список клиентов/обзвон (`database` и
`follow_up`), legacy `search` истории документов. Достаточно замены подготовки
параметра в двух репозиториях, SQL-файлы не менялись. Проверка дублей и валидация
телефонов не изменены. Контракты clients.md / delivery-history.md уточнены.
