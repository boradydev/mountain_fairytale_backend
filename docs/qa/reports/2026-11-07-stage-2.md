## Манифест и команды владельцу

Манифест: `.codex-tmp/qa-seed/manifest.json`, версия `stage2-v1`, anchorDate `2026-11-07`.
Файл игнорируется Git; хранить вместе с базой, не удалять при очистке временных файлов.
Git HEAD зафиксирован в манифесте; сам этап 2 остаётся незакоммиченным по заданию.
Внутри сохранены исходные/изменённые сведения, UUID, CORE-зависимости, история связей,
входные запросы, независимые ожидания, итоги по месяцам и журнал восстановления.

```powershell
.\scripts\qa\qa.ps1 check
.\scripts\qa\qa.ps1 seed
.\scripts\qa\qa.ps1 seed-status
```

Во Flutter подключиться к QA API и открыть «История доставок» → «Документы», период
23.09.2026–07.11.2026, включить отменённые. На 05.11 открыть суммы **275.00 / 81.39 / 91.50**.
Во втором маршруте видны свободные строки и недоставленная точка; в самовывозе три
покупки. Для ручных действий доступны отдельные QA-MANUAL-20…29, включая карточки
«Реквизиты», «Не-доставлено», «История», «Без-заказов». CORE не редактировать.
Общие QA-справочники выбирать, а не менять: они зафиксированы в coreDependencies.

## Ограничения и неподготовленные случаи

- Разные ненулевые исторический представитель и получатель не подготовлены: публичного согласованного переназначения исторических начислений нет. Подготовлен штатный случай route6: исторический rep2 и отсутствующий получатель после деактивации.
- createdAt реальный; плановые даты не подменяли SQL. Последние 30 дней относительно сегодня со временем перестанут совпадать с фиксированной anchorDate.
- Ручная визуальная проверка Flutter/PDF и полная проверка поиска ещё не проведены; инструкция для предварительного осмотра подготовлена.
- При неизвестных данных/утрате манифеста/конфликте CORE — отказ и решение владельца, автоматического удаления или reset нет.
- Общие месячные итоги меняются от последующих MANUAL-продаж; эталонные ожидания CORE остаются в манифесте.
- Дефектов бизнес-логики приложения первичная сверка не выявила. Отказ memo был ошибкой входного запроса генератора; контракт не меняли.
