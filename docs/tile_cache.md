# Постоянный кэш тайлов Geoapify

Кэш включён по умолчанию. Новые зависимости, PostgreSQL-таблицы и миграции не нужны.
Каталог создаётся автоматически при первом запросе карты, исключён из Git.
В нём находится файл `osm-carto-v1.sqlite3` с PNG и служебными метаданными.
API-ключ в файл кэша не записывается.

| Переменная окружения backend | По умолчанию |
| --- | --- |
| `GEOAPIFY_TILE_CACHE_DIR` | `.cache/geoapify-tiles` относительно корня backend-проекта |
| `GEOAPIFY_TILE_CACHE_MAX_BYTES` | `21474836480` (20 ГиБ) |

Путь рекомендуется задавать абсолютный. Минимальный допустимый лимит — 1048576 байт.
Изменения настроек применяются после перезапуска backend. Уменьшенный лимит
применяется при следующей записи тайла. Папка не резервирует 20 ГиБ заранее.
Бюджет включает основной SQLite-файл с индексами; для журнала транзакции нужно
оставить дополнительное свободное место. Время последнего использования
обновляется с точностью до часа, чтобы не записывать диск при каждом кадре карты.

Тайл проверяется при использовании, если прошло 30 дней с успешной проверки.
Старое изображение сразу отдаётся, обновление происходит в фоне. `304` сохраняет
изображение и продлевает срок; `200` заменяет изображение. При отсутствии ETag
выполняется обычная загрузка. Ошибка проверки откладывает повтор на час;
короткая задержка попытки также сохраняется перед началом фонового запроса.
Тайлы не удаляются по возрасту. При заполнении кэша вытесняются давно неиспользуемые.
Проверки через Geoapify не считаются гарантированно бесплатными по кредитам.

При ошибке доступа/записи SQLite выдаётся предупреждение без ключа и URL провайдера,
карта использует память и сеть. Это означает, что после перезапуска при неисправном
хранилище сохранность кэша не гарантируется. Повреждённая PNG-сигнатура записи
приводит к повторной загрузке. Транзакции защищают от частично записанных изображений.

## Подключение в будущем Docker Compose

Фрагмент для добавления к будущему сервису backend (не полный Compose-файл):

```yaml
services:
  backend:
    environment:
      GEOAPIFY_TILE_CACHE_DIR: /var/cache/geoapify
      GEOAPIFY_TILE_CACHE_MAX_BYTES: "21474836480"
    volumes:
      - geoapify_tiles:/var/cache/geoapify

volumes:
  geoapify_tiles:
```

Пользователь контейнера должен иметь право записи в каталог. Подключать нужно
весь каталог, включая временные SQLite-журналы. Named volume сохраняется при
обычном пересоздании контейнера; удаление volume, в том числе `down -v`, удалит кэш.
Использовать локальный диск/volume; общий SQLite-файл не предназначен для сетевых
файловых систем или нескольких серверов. На одном сервере workers могут разделять
файл, но редкие одновременные проверки одного тайла между workers возможны.

Во Flutter отдельного дискового хранилища нет: PNG-кэш в памяти до 16 МиБ/256 записей,
с повторным запросом backend через пять минут при использовании. Он теряется при
перезапуске приложения, постоянный серверный кэш при этом остаётся.
