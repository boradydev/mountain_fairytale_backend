Дата: 22 октября 2026 года.
Статус: код и запуск в Ubuntu VM проверены; приёмка Flutter и запуск после

## Подготовлено

- Многостадийный Dockerfile: рабочий образ без root, Poetry и тестовых
  зависимостей; отдельный test target с зависимостями из poetry.lock.
- Python-образ и PostgreSQL закреплены digest. Рабочий Python — 3.13.17,
  PostgreSQL — 17.11.
- Compose для API, PostgreSQL и отдельного разового migrate.
- Постоянные тома PostgreSQL и кэша карт, ротация логов, healthcheck.
- Версия backend 1.0.0 из pyproject.toml; один worker.
- Публичные `/health/live` и `/health/ready` с версией/commit SHA.
- Скрипты установки Docker, создания отдельного окружения и сетевого ограничения.
- systemd units автозапуска Compose и правила DOCKER-USER.
- CI для PR/push в master: lock-check, Ruff изменённых Python-файлов,
  unit/API/repository tests с временной PostgreSQL и сборка образа.
- httpx явно объявлен как тестовая зависимость, Ruff/Pyright перенесены
  в dev-группу. Существующие версии зависимостей не обновлялись целенаправленно.

## Остаётся для приёмки

- Проверить автозапуск **самой VM** после выключения/включения Windows.
  Чтение настроек Hyper-V через Get-VM недоступно текущему процессу из-за
  прав Windows. Автозапуск внутри Ubuntu проверен отдельно реальной перезагрузкой.
- Запустить Flutter с `--dart-define=API_BASE_URL=http://192.168.0.25:8000`
  и проверить основные сценарии с клиентского ПК. Flutter-код и сборки
  в этом этапе не менялись.
- В приватном терминале задать удобный пароль admin через существующий CLI:
  `sudo docker compose exec api python -m src.common.cli.main admin change-password`.
  Выполнять из `/opt/mountain-fairytale`. Исходный случайный пароль находится
  только в серверном `.env`; он не публикуется в отчёте или чате.
- Добавить серверный `GEOAPIFY_API_KEY`, чтобы заработали карты,
  геокодирование и оптимизация. Ключ разработки не переносился.
- Проверить проектные изменения перед коммитом. Workflow подготовлен локально,
  но не отправлен на GitHub и не запускался там.
