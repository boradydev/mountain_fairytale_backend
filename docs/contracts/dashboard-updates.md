# Обновления дашборда API ↔ Flutter

Область: только списки клиентов и дней доставки. Backend работает одним
процессом в Docker. Журнал продолжает использовать собственный polling;
просмотр и редактор документов не обновляются этим каналом.

## Запрос

`GET /protected/dashboard-updates` с обычным access token.

| Параметр | Тип | Правило |
| --- | --- | --- |
| `server_id` | UUID | Идентификатор запуска сервера из последнего ответа |
| `version` | integer ≥ 0 | Последняя успешно обработанная версия |
| `timeout` | number 0..25 | Время ожидания в секундах; по умолчанию 25 |

При отсутствии позиции сервер отвечает немедленно. Если версия актуальна,
запрос асинхронно ждёт изменения или таймаута. Ожидание не занимает соединение
с PostgreSQL. Неверные query-параметры дают 422, доступ без авторизации — 401.

## Ответ

Обычная обёртка `StdResponse`, полезная нагрузка в `data`:

```json
{
  "data": {
    "serverId": "0192f0b0-1234-7000-8000-000000000001",
    "version": 153,
    "clientsChanged": true,
    "deliveryDaysChanged": false,
    "reloadRequired": false
  }
}
```

- Изменения объединяются относительно переданной версии. История ID и полные
  списки не передаются. При таймауте без изменений флаги false, версия сохраняется.
- Неизвестный запуск, отсутствующая позиция либо версия больше текущей дают
  `reloadRequired: true` и оба флага true. Это позволяет восстановиться после
  перезапуска процесса без постоянного хранилища уведомлений.
- Версии хранятся в памяти конкретного приложения, отдельно для двух разделов.
  Общая версия повышается синхронно после успешного COMMIT, без await между
  подтверждением транзакции и публикацией. Откат и запрос без изменений не уведомляют.
  Обработчик `on_committed` передаётся явно через конструкторы фабрик и UOW
  клиентов, документов, представителей и способов оплаты. При сборке приложения
  это `dashboard_changes.publish`; зависимости в `session.info` не хранятся.
  Общий UOW использует типизированный callback и не зависит от фичи дашборда.
- События клиентов, представителей и способов оплаты меняют версию клиентов
  (имена связанных справочников отображаются в модели клиента).
  События документов, точек и позиций меняют версии обоих списков: документы
  влияют также на последнюю доставку и режим обзвона клиента.
- Edit lock, вход, смена пароля и журнал сами по себе не уведомляют дашборд.
- Механизм предназначен для одного процесса; запуск нескольких workers требует
  общего механизма доставки уведомлений. Миграции для текущего варианта не нужны.

## Flutter

1. При открытии дашборда или возвращении приложения запросить позицию с timeout=0.
2. После этого загрузить оба списка. Полученная перед загрузкой позиция гарантирует,
   что изменения во время загрузки будут замечены следующим запросом.
3. Ожидать с server_id/version и timeout=25. Одновременно отправлен один запрос.
4. При clientsChanged заново загрузить всех клиентов с текущим фильтром активности.
   При deliveryDaysChanged загрузить дни с offset=0 и limit не меньше уже
   загруженного количества (минимум 7), обновить total.
5. Подтвердить версию локально только после успешного обновления затронутых
   списков; затем сразу отправить следующее ожидание. Изменения, возникшие во
   время HTTP-загрузки списков, будут обработаны следующим ответом.

Фоновое обновление не очищает списки и не переводит их в общий экран загрузки.
Сохраняются контроллеры прокрутки, выбранный режим и фильтр. Открытые формы
не перезаполняются. Изменение локального фильтра или успешное локальное
редактирование делает устаревший фоновый ответ недействительным; синхронизация
повторяется без продвижения позиции.

При уходе со вкладки, сворачивании приложения или завершении сессии ожидание
отменяется, повторные запросы прекращаются. При возвращении выполняется полная
сверка. Таймаут транспорта для long polling — 35 секунд; обычные запросы
сохраняют прежние таймауты. Авторизация и обновление access token общие с API.

При ошибке данные остаются на экране. Повторы идут с задержкой 1, 2, 4, 8,
затем максимум 15 секунд; после успешной синхронизации задержка сбрасывается.
Канал не заменяет существующие запросы ручного обновления списков.
