# Общий контракт форм справочников Flutter

Статус: реализовано. Документ фиксирует поведение диалогов клиента, товара,
сотрудника, способа оплаты, торгового представителя, автомобиля и водителя.
Это контракт интерфейса Flutter; он не меняет эндпоинты, схемы, ограничения
уникальности и коды ошибок API отдельных сущностей.

## Создание и редактирование

При создании основное действие называется «Добавить». При редактировании
подпись и действие зависят от сравнения текущих значений с исходными:

| Состояние | Основная кнопка | Действие |
| --- | --- | --- |
| Поля не изменены | ОК | Закрыть без валидации сохранения, поиска дубликатов и PATCH |
| Есть изменения | Сохранить | Проверить форму и сохранить изменённые поля |
| Все изменения возвращены к исходным значениям | ОК | Закрыть без запросов сохранения |

Ширина и положение основной кнопки одинаковы для «ОК» и «Сохранить».
Открытие диалога по-прежнему может загружать необходимые справочники.

Изменённость формы и необходимость поиска дубликатов — независимые признаки.
Например, изменение цены товара включает «Сохранить», но не требует проверки
названия. Смена названия включает и сохранение, и проверку.

## Сравнение значений и PATCH

- Исходное состояние запоминается при открытии формы. Изменённость определяется
  сравнением значений, а не фактом ввода или получения фокуса.
- Сравниваются нормализованные значения: строки без пробелов по краям,
  телефон в представлении для API, канонический госномер, числа после разбора.
  Например, `10`, `10.0` и `10,00` в числовом поле считаются одним значением.
- Дата отсрочки клиента в форме сравнивается с точностью до дня и при изменении
  отправляется с временем `00:00:00`, согласно [контракту клиентов](clients.md).
- Клиентская нормализация не меняет серверные правила сравнения строк,
  регистрозависимости и уникальности.
- PATCH содержит только изменённые поля. Пустой PATCH не отправляется.
- Пропуск nullable-поля сохраняет его значение. Явный `null` отправляется только
  при очищении поля пользователем: например, для комиссии сотрудника, отсрочки
  клиента или его связи со способом оплаты/представителем.
- Ошибочный непустой ввод остаётся изменением; «Сохранить» выполняет обычную
  валидацию и показывает ошибки в соответствующих полях.

Активация, деактивация и смена пароля — отдельные операции. Уже выполненные
операции не отменяются последующим закрытием формы по «ОК» или «Отмена».

## Поля поиска дубликатов

| Сущность | Ключ поиска | Примеры изменений без нового поиска |
| --- | --- | --- |
| Клиент | Имя, телефон и адрес вместе | Порог засыпания, отсрочка, представитель, способ оплаты |
| Товар / услуга | Название | Базовая цена |
| Сотрудник | Логин | Комиссия |
| Способ оплаты | Название | Изменяемых текстовых полей вне ключа нет |
| Торговый представитель API | Имя и телефон вместе | Вознаграждение |
| Автомобиль | Канонический госномер | Модель, текущий пробег |
| Водитель | ФИО | Изменяемых текстовых полей вне ключа нет |

В отдельном demo-источнике представителей поиск остаётся по имени: его
репозиторий не поддерживает составной API-поиск по имени и телефону.
Это не меняет контракт API торговых представителей.

## Автоматическая проверка

1. После изменения полей поиска предыдущий результат становится неактуальным.
   Изменение обычного поля не сбрасывает актуальный результат поиска.
2. Поиск запускается через **600 мс после последнего изменения нормализованного
   ключа**, если все поля ключа заполнены корректно. Неполный или некорректный
   ключ не отправляется серверу.
3. Потеря фокуса не является условием запуска. Пользователю не нужно специально
   переходить в другое поле для начала поиска.
4. При открытии редактирования исходные значения не проверяются повторно.
   Возврат к исходному ключу отменяет отложенную проверку.
5. Во время ожидания паузы показывается статус ожидания завершения ввода.
   При неполных данных виджет объясняет, какие поля необходимо заполнить.
6. Ответ для уже изменённого ключа игнорируется. Закрытие диалога отменяет
   отложенный запуск; завершившийся запрос не обновляет закрытую форму.

## Проверка при сохранении

- Сначала выполняется валидация изменённой формы.
- Если ключ поиска не изменён относительно исходного, поиск не нужен.
- Если для текущего ключа уже получен успешный результат, используется этот
  результат; повторный запрос при нажатии «Сохранить» не отправляется.
- Если запрос для текущего ключа выполняется, сохранение дожидается того же
  запроса, не создавая второй.
- Если актуального результата или запроса нет, проверка запускается сразу,
  без ожидания оставшейся части задержки 600 мс.
- Правила обработки найденных записей, подтверждения создания, активации,
  точных совпадений и ошибок поиска сохраняются в контракте каждой сущности.
- Проверка дубликатов в UI не заменяет серверные ограничения. Конфликт при
  POST/PATCH обрабатывается даже после успешной предварительной проверки.

## Индикаторы и общие компоненты

- `DuplicateCheckStatusWidget` отображает поиск дубликатов своим круговым
  индикатором. Одновременно общая полоска операции формы не показывается.
- `BaseFormDialog` отображает загрузку сохранения, активации и других операций
  формы. Место под индикатор постоянно зарезервировано, чтобы поля и кнопки
  не сдвигались при его появлении и исчезновении.
- `AppDropdown` отображает загрузку своего справочника через `isLoading`:
  отступ от поля — 4 пикселя, высота полоски — 4 пикселя; место сохраняется
  и без загрузки.
- В форме клиента состояния, запросы и ошибки загрузки способов оплаты и
  представителей независимы. Обновление одного справочника не включает
  индикатор другого. При открытии могут загружаться оба справочника.
- Механизм задержки и ожидания запроса общий (`DuplicateCheckCoordinator`),
  состав полей и правила сравнения задаёт конкретная форма. Общие функции
  сравнения нормализованных значений находятся в `core/state/form_editing.dart`.

## Проверки реализации

Flutter-тесты `test/shared/entity_form_editing_test.dart` проверяют все семь
форм: закрытие без запросов, возврат исходных значений, постоянные размеры
основной кнопки, выборочный PATCH, нормализацию чисел, задержку 600 мс и
ожидание выполняющегося поиска при сохранении. Тесты соответствующих сущностей
дополнительно проверяют устаревшие ответы, nullable-поля и обработку дубликатов.
