# Контракт API водителей

Статус: черновик, составлен по текущим HTTP-схемам и описаниям backend.
Это общий контракт для Flutter и FastAPI; при расхождении клиент следует
привести к согласованному контракту.

Основные источники реализации:
- `src/feat/drivers/api/driver_routers.py`
- `src/feat/drivers/api/driver_schemas.py`
- `src/common/api/routers.py`
- `src/common/api/exc_map.py`

## Общие правила

- Все эндпоинты находятся под `/protected/drivers` и требуют access token.
- Токен передаётся в `Authorization: Bearer <token>` или cookie `access-token`.
- Доступен любой аутентифицированной учётной записи; административная роль не требуется.
- Идентификатор `driverId` — UUID, передаваемый строкой.
- Имена JSON-полей используют `camelCase`.
- Успешный ответ обёрнут в `StdResponse`: полезная нагрузка находится в `data`.
- Водители физически не удаляются. Деактивация сохраняет запись и историю.
- Имя длиной от 1 до 120 символов. Уникальность имени не обеспечивается;
  совпадающие и похожие имена допустимы.

## Эндпоинты

### `GET /protected/drivers`

Возвращает список водителей.

Query-параметр `include_deactivated` — необязательный boolean, по умолчанию
`false`. При `false` возвращаются только активные записи; при `true` — активные
и деактивированные.

Ответ `200`:

```json
{
  "data": {
    "drivers": [
      {
        "driverId": "uuid",
        "name": "Иван Иванов",
        "createdAt": "2026-10-11T10:00:00",
        "isActive": true
      }
    ]
  }
}
```

### `GET /protected/drivers/{driver_id}`

Возвращает водителя по UUID. Деактивированные записи тоже доступны по ID.

- `200` — водитель найден; `data` содержит `DriverResp`.
- `401` — нет действительной авторизации.
- `404` — водитель с таким UUID не найден.

### `POST /protected/drivers/create`

Создаёт водителя. Тело запроса:

```json
{ "name": "Иван Иванов" }
```

- `201` — возвращает созданного водителя в `data`.
- `driverId`, `createdAt` и `isActive` назначаются сервером;
  новая запись активна.
- Наличие совпадающего или похожего имени не блокирует создание.
- `401` — нет действительной авторизации.
- `422` — ошибка валидации, в том числе имя пустое или длиннее 120 символов.

### `PATCH /protected/drivers/{driver_id}`

Частично обновляет водителя. Допустимые поля — `name` и `isActive`; требуется
передать хотя бы одно поле. Примеры:

```json
{ "name": "Новое имя" }
```

```json
{ "isActive": false }
```

- `200` — возвращает актуального водителя в `data`.
- `isActive: false` деактивирует запись, `isActive: true` повторно активирует её.
- Пустое тело, некорректное имя или `null` для этих полей дают `422`.
- `401` — нет действительной авторизации.
- `404` — водитель не найден.

### `GET /protected/drivers/check-duplicate?name={name}`

Ищет наиболее похожее имя. `name` обязателен, длина от 1 до 120 символов.
Поиск включает активных и деактивированных водителей. Порог совпадения —
similarity не ниже `0.35`. Лучший кандидат выбирается в таком порядке:

1. similarity по убыванию;
2. абсолютная разница между длиной имени кандидата и запроса по возрастанию;
3. `createdAt` по убыванию;
4. `driverId` по убыванию.

- `200` — `data` содержит лучший `DriverResp` либо `null`, если совпадения не найдены.
- `401` — нет действительной авторизации.
- `422` — параметр отсутствует или не проходит валидацию.
- Результат этой проверки — подсказка; `POST /create` не отклоняет дубликаты.

### Поведение Flutter при возможном совпадении

- Перед созданием Flutter может вызвать `/check-duplicate` и показать
  предупреждение, если сервер нашёл совпадение.
- Предупреждение не блокирует создание: пользователь может продолжить и
  сохранить ещё одну запись.
- Поиск учитывает деактивированных водителей. Если найденная запись
  деактивирована, интерфейс должен явно показать её статус.
- Для найденного деактивированного водителя интерфейс предлагает действие
  «Активировать». Оно отправляет `PATCH` с `{ "isActive": true }`.
- После успешной активации Flutter обновляет список активных водителей и сразу
  выбирает этого водителя в выпадающем поле конструктора маршрута, закрывая
  диалог проверки дубля и диалог создания нового водителя.
- Совпадение имени считается только возможным дублем: у разных людей могут
  быть одинаковые или похожие имена.

### Неактивные водители в выпадающем списке маршрута

- В конструкторе маршрута есть переключатель «Показывать неактивных
  водителей». Его состояние сохраняется между запусками приложения; при первом
  запуске переключатель выключен.
- При выключенном переключателе Flutter запрашивает
  `GET /protected/drivers` (или `include_deactivated=false`). При включённом —
  `GET /protected/drivers?include_deactivated=true`.
- Неактивные записи в выпадающем списке заметно помечаются, например, подписью
  «Неактивен» и приглушённым оформлением.
- Backend запрещает назначать неактивного водителя в маршрут. Поэтому выбор
  такой записи должен предложить действие «Активировать и выбрать»; только
  после успешного `PATCH isActive=true` запись становится выбранным водителем.
- Если пользователь отменяет активацию, текущий выбор водителя не меняется.

## Удаление и деактивация

Отдельного `DELETE`-эндпоинта нет и добавлять его не требуется. Контракт
сохраняет историю водителей: клиент деактивирует запись запросом
`PATCH /protected/drivers/{driver_id}` с телом `{ "isActive": false }`.
Повторная активация выполняется тем же `PATCH` с `isActive: true`.

Во Flutter операцию следует называть `deactivateDriver`, а не `deleteDriver`,
чтобы имя метода соответствовало фактическому поведению.

## Проверка API

- Проверять публичные HTTP-эндпоинты и фактические status code и тело ответа.
- После `POST` и `PATCH` проверять результат через `GET` или список.
- Проверять, что деактивация не удаляет запись, её можно получить по ID и
  включить в список с `include_deactivated=true`, а повторная активация работает.
- Проверять поиск дубликата среди активных и деактивированных записей и то,
  что поиск не блокирует создание.
- Ожидаемое поведение определять по этому контракту, router, schemas и API
  exceptions, а не по внутренней реализации use case или repository.
