# Контракт API комиссионных начислений

Статус: контракт согласован и готов к реализации.

Название раздела во Flutter: **«Комиссии»** или **«Комиссионные начисления»**.
«Комиссионные начисления» точнее описывает расчёт выплат, чем общее
«Вознаграждения»; для короткой подписи переключателя удобно «Представители / Сотрудники».

## Контекст существующей модели

- Торговый представитель (`SalesRepresentative`) и сотрудник (`Employee`) —
  разные сущности с разными UUID и ставками `commissionPercent`.
- Клиент связан с нулём или одним торговым представителем через
  `salesRepresentativeId`. Отсутствие представителя допустимо.
- Продажи хранятся в листах доставки (`delivery_route_sheet`) и самовывоза
  (`pickup_sheet`), дата отчётного периода — `plannedDate`. Отменённый лист
  имеет `isActive=false` и не входит в отчёт; восстановленный снова учитывается.
- Сейчас сумма продажи складывается во Flutter из строк листа: каждая строка
  округляется до двух знаков по `ROUND_HALF_UP`, затем складываются суммы строк
  точки и листа. Backend сейчас не хранит готовую сумму листа. При реализации
  backend вычисляет оборот документа и точки тем же правилом. Для точного
  финансового расчёта цена и начисления хранятся в SQL `NUMERIC` и обрабатываются
  через Decimal.
- Согласовано: начисления должны сохраняться исторически вместе с документом;
  перенос клиента, изменение ставки и изменение статуса клиента не должны
  сами по себе переписывать уже сохранённое начисление.
- Модель снимков: для точки документа сохранять снимок торгового представителя,
  его ставки, оборота точки и начисления; для документа — снимок активных
  сотрудников (кроме admin), их ставок, оборота документа и начислений. Так
  комиссия представителя объясняется через конкретного клиента, а комиссия
  каждого сотрудника рассчитывается со всего оборота документа.
- При редактировании существующие точки сохраняют зафиксированных получателя и
  ставку, а сумма начисления пересчитывается по новой сумме точки. Для новых
  точек берутся текущий представитель и его ставка; удалённые точки удаляются
  вместе с начислениями. Для начислений сотрудников сохраняются получатели и
  ставки снимка документа, сумма пересчитывается по новому обороту документа.
- Восстановление отменённого документа возвращает сохранённые начисления, без
  перерасчёта по текущим ставкам или назначениям.
- Демо-модели Flutter используют числовые ID; API должен возвращать UUID-строки,
  как и остальные backend API.

## Предлагаемый интерфейс

Все маршруты защищённые, требуют действительную авторизацию и используют
`StdResponse` с данными в `data`. Имена полей JSON — `camelCase`.

### Получить месячный отчёт

`GET /protected/commissions?year=2026&month=10`

`year` — год, `month` — месяц от 1 до 12. Месяц общий для обоих режимов.
Ответ сразу содержит сводку и две коллекции; переключатель во Flutter только
меняет отображаемую коллекцию, повторно загружать данные не нужно.

`include_deactivated` — необязательный boolean, по умолчанию `false`;
управляет только составом `salesRepresentatives`:

- `false` — активные представители плюс деактивированные, у которых есть
  закреплённые сейчас клиенты или начисления за выбранный месяц;
- `true` — все представители, включая деактивированных без клиентов и без
  начислений за месяц. Для отсутствующих оборотов и начислений возвращаются нули.

Фильтр не меняет месячную сводку, правила расчёта или состав сотрудников.
Изменение тумблера выполняет повторный запрос за текущий выбранный месяц.

```json
{
  "data": {
    "period": { "year": 2026, "month": 10, "dateFrom": "2026-10-01", "dateTo": "2026-11-01" },
    "summary": {
      "totalTurnover": 1250000.00,
      "representedTurnover": 980000.00,
      "unassignedTurnover": 270000.00,
      "salesRepresentativeCommission": 49000.00,
      "employeeCommission": 62500.00,
      "totalCommissionPayable": 111500.00
    },
    "salesRepresentatives": [
      {
        "salesRepresentativeId": "uuid",
        "salesRepresentativeName": "Иван Иванов",
        "isActive": true,
        "assignedClientsCount": 12,
        "commissionRateBreakdown": [
          { "commissionPercent": 5.0, "turnoverBase": 980000.00, "commissionPayable": 49000.00 }
        ],
        "clientsCount": 12,
        "ordersCount": 27,
        "turnover": 980000.00,
        "commissionPayable": 49000.00
      }
    ],
    "employees": [
      {
        "employeeId": "uuid",
        "username": "manager",
        "role": "employee",
        "commissionRateBreakdown": [
          { "commissionPercent": 5.0, "turnoverBase": 1250000.00, "commissionPayable": 62500.00 }
        ],
        "turnoverBase": 1250000.00,
        "commissionPayable": 62500.00
      }
    ]
  }
}
```

Предлагаемые значения:

- `totalTurnover` — оборот всех учитываемых листов за месяц, каждая продажа
  учитывается один раз.
- `representedTurnover` — оборот клиентов, закреплённых за представителями;
  `unassignedTurnover` — оборот клиентов без представителя.
- `salesRepresentativeCommission` — сумма начислений представителям.
- `employeeCommission` — сумма начислений сотрудникам, не имеющим роль `admin`,
  согласно сохранённым в документах снимкам. В неё входят также деактивированные
  сотрудники с начислением за выбранный месяц.
- `totalCommissionPayable` — сумма двух видов начислений; оборот сотрудников
  не прибавляется повторно к обороту представителей.
- В карточке сотрудника `commissionRateBreakdown` описывает ставки и оборотные
  базы из снимков документов за месяц. `turnoverBase` в каждой строке — оборот
  документа, база комиссии сотрудника — весь оборот документа, включая клиентов
  без представителя. У активного сотрудника с нулевой ставкой начисление равно
  `0.00`.
- `ordersCount` — число учитываемых листов, в которых есть клиент; лист с
  несколькими товарами клиента считается одним заказом этого клиента. Лист с
  нулевой суммой тоже считается заказом.
- По умолчанию в списке представителей возвращаются все активные представители, а также
  деактивированные представители, у которых есть закреплённые сейчас клиенты
  (включая деактивированных клиентов) или начисление за выбранный месяц.
  Наличие закреплённых клиентов позволяет открыть карточку уволенного
  представителя и передать или снять клиентов независимо от выбранного месяца
  и наличия оборота. `isActive` задаёт статус представителя,
  `assignedClientsCount` — число закреплённых за ним сейчас клиентов.
- В списке сотрудников возвращаются все
  активные не-admin сотрудники (в том числе с нулевой ставкой), а также
  деактивированные не-admin сотрудники, у которых есть начисление за выбранный
  месяц. Так уволенный сотрудник виден в месяце с сохранённым начислением и
  пропадает из последующих месяцев, если новых начислений ему не создавалось.

### Детали представителя и его клиентов

`GET /protected/commissions/sales-representatives/{sales_representative_id}?year=2026&month=10`

```json
{
  "data": {
    "salesRepresentativeId": "uuid",
    "salesRepresentativeName": "Иван Иванов",
    "isActive": true,
    "assignedClientsCount": 2,
    "commissionRateBreakdown": [
      { "commissionPercent": 5.0, "turnoverBase": 120000.00, "commissionPayable": 6000.00 }
    ],
    "clientsCount": 2,
    "ordersCount": 7,
    "turnover": 120000.00,
    "commissionPayable": 6000.00,
    "clients": [
      {
        "clientId": "uuid",
        "clientName": "ООО Ромашка",
        "phone": "+79991234567",
        "ordersCount": 4,
        "turnover": 80000.00,
        "lastOrderDate": "2026-10-20",
        "commissionPayable": 4000.00
      }
    ]
  }
}
```

Детали считаются для того же месяца, что и сводка. `commissionPayable` в строке
клиента — точная сумма начисления по сохранённым снимкам. Если ставка менялась,
для клиента возвращаются отдельные элементы `commissionRateBreakdown`. Flutter
округляет значения строк и строит отображаемые итоги из округлённых строк; итог
может отличаться на несколько копеек от округления точной суммы.

### Переназначить или снять всех клиентов представителя

`PUT /protected/sales-representatives/{sales_representative_id}/clients/assignment`

```json
{ "targetSalesRepresentativeId": "uuid" }
```

Чтобы снять представителя, передать явный `null`:

```json
{ "targetSalesRepresentativeId": null }
```

Операция атомарно меняет представителя у всех клиентов исходного представителя
и возвращает число изменённых записей:

```json
{ "data": { "updatedClientsCount": 12, "targetSalesRepresentativeId": "uuid" } }
```

При снятии клиентов поле ответа `targetSalesRepresentativeId` равно `null`.
Неизвестный исходный или целевой ID — `404`; передача самому себе — `422`.
Переназначение не удаляет клиентов и не меняет их активность. Исходный
представитель может быть активным или деактивированным. Целевой представитель
должен быть активным; попытка передать клиентов деактивированному получателю
возвращает `409`. Передаются только клиенты, закреплённые за исходным
представителем на момент операции; исторические начисления не переносятся.

## Общие правила периода и денег

- Месяц задаётся как целые `year` и `month`; диапазон дат полуоткрытый:
  `plannedDate >= dateFrom AND plannedDate < dateTo`.
- Учитываются активные листы обоих типов (`delivery_route_sheet` и
  `pickup_sheet`) по `plannedDate`. Отменённые исключены; нулевой лист считается
  заказом.
- Начисление фиксируется при сохранении документа как оборотная база × ставка /
  100 без округления API. При редактировании сумма пересчитывается по
  зафиксированным получателю и ставке; при восстановлении снимки возвращаются.
- Согласованное решение: денежные значения хранятся точно как Decimal / SQL
  `NUMERIC`; API передаёт значения без округления. Flutter округляет видимые
  значения до двух знаков и строит отображаемые итоги из округлённых строк.
  Сумма строк может отличаться на несколько копеек от округления точной суммы;
  это допустимо для информационных месячных оборотов и начислений.
- Точные начисления конкретного представителя/сотрудника рассчитываются при
  сохранении документа и сохраняются в снимках; Flutter их заново по ставке не
  рассчитывает, а форматирует и суммирует для показа.
- `401` — нет авторизации; `404` — неизвестный сотрудник/представитель;
  `422` — неверный месяц или год; `500` — внутренняя ошибка расчёта.

## Переключатель и сводная карточка во Flutter

- Переключатель сегментированный, по визуальному образцу дашборда:
  **«Представители» / «Сотрудники»**.
- В режиме «Представители» рядом с переключателем находится тумблер
  **«Деактивированные»** в стиле списка клиентов на дашборде. По умолчанию
  выключен; включение передаёт `include_deactivated=true` и показывает всех
  представителей. При выключенном тумблере уволенные с клиентами или начислениями
  за месяц остаются видимыми по согласованному базовому правилу.
  Значение тумблера сохраняется в состоянии текущей пользовательской сессии,
  в том числе при смене месяца и режима. В режиме «Сотрудники» тумблер скрыт и
  на список сотрудников не влияет.
- Выбранный месяц один и применяется к сводке, обеим вкладкам и диалогу
  представителя.
- Сводная карточка может всегда показывать общий оборот и общую сумму к
  выплате, а также разбивку суммы к выплате на представителей и сотрудников.
  При выборе сегмента дополнительно показывается соответствующий оборот:
  закреплённый за представителями либо общий оборот как база сотрудника.
- В карточке представителя: имя, ставка, оборот, сумма начисления; при открытии
  — итоги и клиенты с числом заказов, оборотом, датой последнего заказа и
  начислением к выплате.
- Действия «Передать клиентов» и «Снять представителя» выполняют массовую
  операцию из API, после успеха диалог обновляет данные для текущего месяца.
- Уволенный представитель обозначен статусом «Деактивирован». Его карточка
  при выключенном тумблере доступна, пока есть закреплённые клиенты или начисления
  за выбранный месяц; при включённом доступна независимо от этих условий.
  Список в диалоге объединяет текущих закреплённых клиентов и клиентов с
  историческими начислениями за месяц без дублирования одного клиента.
  При `assignedClientsCount=0` действия передачи и снятия недоступны.

## Согласованные решения

1. **История начислений (согласовано).** Получатель и ставка фиксируются при
   сохранении. Переназначение клиента и изменение ставки не переписывают снимки.
   При редактировании существующих точек сохраняются их получатель и ставка,
   новые точки используют актуальные настройки, удалённые точки удаляются вместе
   с начислением. Восстановление документа возвращает исходные начисления.
2. **Период и заказы (согласовано).** Включаются доставка и самовывоз по
   `plannedDate`, отменённые исключаются, нулевые листы считаются заказом.
3. **Округление (согласовано).** Хранение и API используют точные значения;
   Flutter округляет отображаемые строки до двух знаков и суммирует показанные
   значения. Возможное расхождение в несколько копеек допустимо.
4. **Сотрудники в отчёте (согласовано).** Показываем всех активных не-admin
   сотрудников и деактивированных не-admin сотрудников, имеющих начисление в
   выбранном месяце. Старые начисления остаются в месяце их сохранения; после
   деактивации новые начисления не создаются. Администраторы не показываются и
   комиссию не получают.
5. **Клиенты в диалоге и массовой передаче (согласовано).** Показываем также
   деактивированных клиентов и их исторические начисления; массовая передача или
   снятие затрагивает активных и деактивированных клиентов. У клиента без
   начисления в месяце показываем нулевые показатели. Детали прошлого месяца
   показывают клиентов по сохранённым начислениям за тот месяц, даже если их
   текущее назначение позже изменилось.
6. **Множественные сотрудники с ненулевой ставкой (согласовано).** Каждый
   такой сотрудник получает свой процент от полного общего оборота; проценты
   складываются.
7. **Доступ (согласовано).** Просмотр отчёта и переназначение клиентов доступны
   всем авторизованным пользователям; отдельная роль для этой операции сейчас
   не требуется.

8. **Ставки в отчёте (согласовано).** В деталях ставки показываются отдельными
   строками из сохранённых снимков. Если в месяце применялась одна ставка,
   разбивка содержит одну строку; при смене ставки — несколько. Сводный процент
   вместо этой разбивки не показывается.
9. **Точность денежных значений (согласовано).** Цены, обороты и начисления
   хранятся как SQL `NUMERIC` и обрабатываются Decimal. API передаёт точные
   значения; Flutter округляет отображаемые суммы.

Контракт согласован и может использоваться как основа для реализации backend
и интеграции Flutter.
