# Контракт API способов оплаты для Flutter

Статус: контракт фиксирует текущий HTTP API FastAPI. Flutter реализует клиент
в соответствии с этим документом.

## Авторизация и общий формат

- Все запросы требуют access token в заголовке
  `Authorization: Bearer <accessToken>`; cookie `access-token` также поддерживается.
- Базовый путь: `/protected/payment-methods`.
- Идентификатор `paymentMethodId` — UUID, передаваемый в JSON и URL строкой.
- JSON-поля используют `camelCase`. Исключение: query-параметр списка называется
  `include_deactivated`.
- Успешные ответы обёрнуты в `StdResponse`; полезная нагрузка находится в `data`.
- Flutter читает `data` и игнорирует остальные поля общей обёртки. Пагинации нет:
  справочник способов оплаты небольшой, сервер возвращает список целиком.
- Доступен любому авторизованному пользователю; административная роль не нужна.

Схема `PaymentMethod`:

```json
{
  "paymentMethodId": "0199abc0-1234-7000-8000-000000000001",
  "name": "Наличные",
  "createdAt": "2026-10-12T10:00:00",
  "isActive": true
}
```

`createdAt` — дата и время в ISO 8601 без часового пояса, как возвращает API.
Flutter разбирает и хранит это значение без самостоятельного добавления или
пересчёта часового пояса. Поля `paymentMethodId`, `createdAt` и `isActive`
назначает сервер. Новый способ оплаты всегда создаётся активным.

## Эндпоинты

### `GET /protected/payment-methods`

Возвращает способы оплаты. Query-параметр `include_deactivated` — boolean,
по умолчанию `false`. При `false` возвращаются только активные записи; при
`true` — активные и деактивированные. Записи отсортированы по `createdAt` по
убыванию: сначала новые, затем старые.

Ответ `200`:

```json
{
  "data": {
    "paymentMethods": [
      {
        "paymentMethodId": "0199abc0-1234-7000-8000-000000000001",
        "name": "Наличные",
        "createdAt": "2026-10-12T10:00:00",
        "isActive": true
      }
    ]
  }
}
```

### `GET /protected/payment-methods/{payment_method_id}`

Возвращает способ оплаты по UUID. Деактивированные записи также доступны по ID.

- `200` — запись найдена, объект находится в `data`.
- `401` — нет действительной авторизации.
- `404` — UUID не найден.

### `POST /protected/payment-methods/create`

Создаёт способ оплаты. Тело запроса:

```json
{ "name": "Наличные" }
```

- `201` — созданный объект находится в `data`; новая запись имеет `isActive: true`.
- `401` — нет действительной авторизации.
- `409` — способ оплаты с таким же именем уже существует.
- `422` — ошибка валидации.

### `PATCH /protected/payment-methods/{payment_method_id}`

Частично обновляет способ оплаты. Можно передать непустое подмножество полей
`name` и `isActive`.

Переименование:

```json
{ "name": "Оплата картой" }
```

Деактивация или повторная активация:

```json
{ "isActive": false }
```

- `200` — актуальный объект находится в `data`.
- `401` — нет действительной авторизации.
- `404` — UUID не найден.
- `409` — новое имя уже занято.
- `422` — пустое тело, `null` для изменяемого поля или ошибка валидации.

Физического удаления нет. Для удаления из активного списка отправляется PATCH с
`{"isActive": false}`; для восстановления — с `{"isActive": true}`.

### `GET /protected/payment-methods/check-duplicate?name={name}`

Ищет наиболее похожее имя. `name` обязателен, длина — от 1 до 120 символов.
Параметр нужно кодировать как URL query component.

- `200` — `data` содержит найденный объект или `null`, если совпадений нет.
- `401` — нет действительной авторизации.
- `422` — параметр отсутствует или не проходит валидацию.

Поиск учитывает активные и деактивированные записи. Порог сходства — `0.35`;
возвращается один лучший кандидат. Кандидаты ранжируются в таком порядке:

1. similarity по убыванию;
2. `createdAt` по убыванию;
3. `paymentMethodId` по убыванию.

Это подсказка, а не проверка, блокирующая создание: похожие, но не идентичные
имена разрешены.

## Правила полей и ошибок

- `name` обязателен при создании и имеет длину от 1 до 120 символов.
- Имя уникально при точном совпадении; сравнение регистрозависимое, пробелы не
  нормализуются. Например, `Наличные` и `наличные` — разные имена.
- Успешное создание возвращает HTTP `201`; остальные успешные операции — HTTP `200`.
- При ошибке FastAPI возвращает HTTP status и поле `detail`; при ошибке валидации
  `detail` может быть массивом ошибок.

## Связь с клиентами

В API клиентов поле `defaultPaymentMethodId` — UUID-строка или `null`, а
`defaultPaymentMethodName` — имя способа оплаты или `null`. При отправке клиента
Flutter использует `defaultPaymentMethodId`, а не имя. Серверное поле ID ссылается
на `paymentMethodId` из этого контракта.

В новом выборе Flutter показывает только активные способы оплаты. Если у клиента
уже установлен способ оплаты, который позднее деактивировали, Flutter сохраняет
и отображает его как текущее значение; деактивация справочника не очищает ссылку
клиента. Деактивированный способ нельзя выбрать заново, пока его не активируют.
