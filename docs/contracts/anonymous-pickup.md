# Анонимные покупки в самовывозе

Статус: этап 1 реализован в рабочих ветках, 03.11.2026. Коммиты и выпуск выполняет
владелец после просмотра изменений. Backend 1.2.0 требует Flutter 1.3.0.

## Данные и API

Используются общие документы, точки и товары. Один документ самовывоза содержит
несколько покупок, каждая представлена точкой с собственными товарами и оплатой.

- В самовывозе `clientId` отсутствует или равен `null`; UUID клиента в POST/PATCH
  возвращает `422`. В доставке клиент обязателен.
- Ответ точки содержит `clientId`, `salesRepresentativeId`,
  `salesRepresentativeName`, `defaultPaymentMethodId`, `defaultPaymentMethodName`
  со значением `null`. `clientName`, `phone`, `address`, `clientAddress`,
  `deliveryDetails` — пустые строки. `pointId` и связь с документом сохраняются.
- `paymentMethodId` — сохранённый выбор конкретной покупки. Имя способа оплаты
  разрешается из справочника при чтении. Выбор не меняет настройки клиента.
- `null` оплаты допустим по прежним правилам. Отсутствие поля при создании даёт
  `null`, при PATCH существующей точки сохраняет прежнюю оплату. UUID проверяется.
- При PATCH сохранённые покупки идут в прежнем относительном порядке, новые —
  после них. Удалять покупки разрешено. Перестановка и вставка новой покупки
  перед сохранённой возвращают `422`. `position` пересчитывается с нуля.
- `points` полностью заменяет состав документа; `points: []` очищает его.
  Товары, цены, округления, пустые коллекции и жизненный цикл документа работают
  по [общему контракту](delivery_document.md).

Пример запроса создания:

```json
{
  "plannedDate": "2026-11-03",
  "points": [
    {"clientId": null, "paymentMethodId": "uuid", "items": []},
    {"items": []}
  ]
}
```

Для редактирования у существующей покупки передают `pointId`, у документа —
`expectedRevision`. Ревизии, блокировки, повтор создания, аудит, отмена и
восстановление сохраняются.

## Экран

Плановая дата относится ко всему документу. Вместо панели клиентов кнопка
**«Добавить покупку»** добавляет карточку в конец списка. Карточки подписаны
«Покупка 1», «Покупка 2» и т. д. В каждой доступны товары и способ оплаты;
клиент, адрес, телефон, представитель и перетаскивание отсутствуют.

Создание, просмотр, редактирование, явное сохранение, отмена правок и восстановление
связи работают по существующим правилам. Отмена правок возвращает сохранённую
оплату. Локальный ключ новой покупки сохраняет её состояние при изменении строк
до получения серверного UUID. В документах дня самовывоз показывает число покупок.

## Миграция и выпуск

Новая Alembic-ревизия `82ac739e051d` следует за `7b9d2c4a1e60`:

1. Разрешает `NULL` в `points.client_id`.
2. Отвязывает клиентов у всех точек `pickup_sheet`, включая отменённые документы.
   Владелец подтвердил, что старые самовывозы связаны с фиктивной карточкой.
3. Убирает снимок получателя, ставку и начисление торгового представителя этих
   покупок; оборот и начисления сотрудников документа сохраняются.
4. Повышает ревизии самовывозов для обнаружения ранее открытых редакторов.

Сохраняются UUID, документы, точки, товары, цены, порядок и сохранённая оплата,
включая неизвестный `null`. Клиенты справочника и точки доставки не меняются.
Прежние записи аудита остаются историческими записями. Анонимные покупки не
попадают в сводку последнего заказа клиента. Отчёт продаж учитывает их по
сохранённой оплате; документы дня возвращают все покупки с товарами.

Перед обновлением production подготовить резервную копию и выпуск Flutter 1.3.0.
Обновить backend 1.2.0 с миграцией штатной процедурой и установить новый Flutter.
Старые клиенты блокируются через `client_compatibility.toml`. После установки
проверить старый самовывоз и новый документ с несколькими покупками и оплатой.

`downgrade` явно отказывает, если есть точки без клиента: автоматическое удаление
покупок или создание фиктивных клиентов не выполняется. Для полного возврата
к старой системе требуется согласованное восстановление копии до обновления.
В рамках разработки обновление production не выполнялось.
