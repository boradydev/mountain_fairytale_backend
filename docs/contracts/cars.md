# Контракт API автомобилей

Статус: согласован и реализован для российских регистрационных знаков типа 1.

Основные источники реализации:
- `src/feat/cars/api/car_routers.py`
- `src/feat/cars/api/car_schemas.py`
- `src/common/api/routers.py`
- `src/common/api/exc_map.py`

## Общие правила

- Все эндпоинты находятся под `/protected/cars` и требуют access token.
- Токен передаётся в `Authorization: Bearer <token>` или cookie `access-token`.
- Доступен любой аутентифицированной учётной записи; административная роль не требуется.
- `carId` — UUID, передаваемый строкой.
- JSON-поля request/response используют `camelCase`; query-параметры используют
  имена, заданные в router, в том числе `include_deactivated`.
- Успешный ответ обёрнут в `StdResponse`; полезная нагрузка находится в `data`.
- Госномер уникален. Запись сохраняется при деактивации, поэтому её номер
  остаётся занятым и совпадение с деактивированной машиной тоже считается дублем.

Поля автомобиля в `CarResp`:

```json
{
  "carId": "uuid",
  "model": "Газель Бизнес",
  "number": "А123КХ126",
  "currentMileage": 12500.0,
  "isActive": true
}
```

## Эндпоинты

### `GET /protected/cars`

Возвращает список автомобилей.

Query-параметр `include_deactivated` — необязательный boolean, по умолчанию
`false`. При `false` возвращаются только активные автомобили; при `true` —
активные и деактивированные.

Ответ `200` содержит `data.cars` — список `CarResp`.

### `GET /protected/cars/check-duplicate?number={number}`

Ищет автомобиль по полному значению госномера среди активных и
деактивированных записей. `number` обязателен; перед поиском нормализуется и
проверяется как российский регистрационный знак типа 1.

- `200` — `data` содержит `CarResp`, если номер найден, иначе `null`.
- `401` — нет действительной авторизации.
- `422` — query-параметр отсутствует или не проходит валидацию.
- Отсутствие совпадения является нормальным результатом, не `404`.

### `GET /protected/cars/{car_id}`

Возвращает автомобиль по UUID независимо от его активности.

- `200` — автомобиль найден; `data` содержит `CarResp`.
- `401` — нет действительной авторизации.
- `404` — автомобиль с таким UUID не найден.
- Некорректный UUID в пути отклоняется валидацией FastAPI.

### `POST /protected/cars/create`

Создаёт автомобиль. Тело запроса:

```json
{
  "model": "Газель Бизнес",
  "number": "А123КХ126",
  "currentMileage": 0
}
```

- `model`: обязательно, 1–100 символов.
- `number`: обязательно; допускается формат с пробелами и латинскими
  визуальными двойниками, сервер возвращает нормализованное значение.
- `currentMileage`: неотрицательное число, по умолчанию `0`.
- `201` — возвращает созданный `CarResp` в `data`; `carId` назначает сервер,
  новая запись активна.
- `401` — нет действительной авторизации.
- `409` — госномер уже занят существующим автомобилем, включая деактивированный.
- `422` — ошибка валидации полей.

### `PATCH /protected/cars/{car_id}`

Частично обновляет автомобиль. Допустимые поля: `model`, `number`,
`currentMileage`, `isActive`. Нужно передать хотя бы одно поле. Все числовые
значения пробега неотрицательны; уменьшить уже сохранённый пробег нельзя.

Примеры:

```json
{ "currentMileage": 13000 }
```

```json
{ "isActive": false }
```

- `200` — возвращает актуальный `CarResp` в `data`.
- `isActive: false` деактивирует машину, `isActive: true` повторно активирует её.
- `409` — `number` уже используется другим автомобилем.
- `401` — нет действительной авторизации.
- `404` — автомобиль не найден.
- `422` — пустое тело, недопустимые значения или попытка уменьшить пробег.
- `null` для полей автомобиля не допускается.

## Деактивация и назначение в маршрут

- Отдельного `DELETE`-эндпоинта нет. Деактивация и повторная активация
  выполняются через `PATCH isActive`; физически автомобиль не удаляется.
- Неактивный автомобиль нельзя назначить в маршрут. Перед назначением он
  должен быть повторно активирован.
- Деактивированный автомобиль остаётся доступен по ID, может быть включён в
  список через `include_deactivated=true`, а его госномер остаётся уникальным.

## Поведение Flutter при совпадении номера

- При совпадении с активным автомобилем открыть его существующую запись для
  редактирования, не создавать новую.
- При совпадении с деактивированным автомобилем предложить действие
  «Активировать и выбрать». После успешной активации обновить список и выбрать
  этот автомобиль в конструкторе маршрута.
- В списке выбора машин нужен сохранённый переключатель показа
  деактивированных записей. Деактивированные машины помечаются явно; для них
  доступно действие «Активировать и выбрать».
- Создание или изменение номера, занятого другим автомобилем, всё равно может
  завершиться `409`; Flutter должен обработать этот конфликт, даже если перед
  сохранением была выполнена проверка дубля.

## Форматирование и проверка госномера

Для российских знаков типа 1 ГОСТ задаёт последовательность из буквы, трёх
цифр, двух букв и двух- или трёхзначного кода региона. Применяются только
буквы `АВЕКМНОРСТУХ`. ГОСТ определяет форматы самих знаков, а правила обработки
пользовательского ввода приложение устанавливает отдельно.

Flutter форматирует ввод по мере набора и показывает номер как
`А123КХ 126`: разделитель добавляется перед кодом региона. Форматтер принимает
частичный ввод, приводит буквы к верхнему регистру и не даёт ввести символы,
которые не подходят текущей позиции. Полная проверка выполняется при
сохранении; допустимы две или три цифры региона.

В API и базе номер передаётся в каноническом виде без пробела, например
`А123КХ126`. Перед форматированием Flutter удаляет пробелы, а после получения
ответа форматирует каноническое значение для показа. Латинские буквы, визуально
совпадающие с разрешёнными кириллическими (`A`, `B`, `E`, `K`, `M`, `H`, `O`,
`P`, `C`, `T`, `Y`, `X`), преобразуются в соответствующие кириллические.
Маркировка `RUS` на знаке не входит в значение госномера.

Проверка полного значения после нормализации: `^[АВЕКМНОРСТУХ][0-9]{3}[АВЕКМНОРСТУХ]{2}[0-9]{2,3}$`.

Backend повторяет нормализацию и валидацию на `create`, `patch` и
`check-duplicate`, а уникальность проверяет по каноническому номеру. Flutter-
форматтер улучшает ввод, но не заменяет проверку на сервере. Ограничение
`cars_number_format_check` создаётся в исходной миграции таблицы `cars`.
На текущем этапе разработки база пересоздаётся, поэтому отдельная миграция
преобразования существующих номеров не нужна; правила описаны в `CONVENTIONS.md`.

Нормативные источники: [карточка действующего ГОСТ Р 50577-2018 в Росстандарте](https://protect.gost.ru/gost/details/86504e75-dbfe-47fa-b298-1a7b69d1a4b7) и [текст требований к структуре знаков и допустимым буквам](https://www.consultant.ru/document/cons_doc_LAW_318486/d5ec98020f899e71d9c12efd9eec8515135c72aa/).
