# Этап 2. Общая история доставок и самовывозов

Статус: реализовано и проверено локально в ветках `codex/delivery-history`.
Изменения этапа не закоммичены; релиз Flutter не создавался.
Решения от 03.11.2026. API и правила ответа: [контракт истории](delivery-history.md).

## Основной сценарий

Пользователь выбирает ограниченный период и вводит в одну строку название
клиента, адрес или телефон. Получает карточки документов, в которых встречается
подходящий клиент, чтобы узнать, когда и что он покупал, какой водитель и какая
машина выполняли доставку. Из карточки открывает исходный документ полностью.
Поиск общего названия работает сразу по разным карточкам одного фактического
клиента; адрес/телефон позволяют уточнить выборку.

## Согласовано

- Название вкладки — «История доставок»; заголовок экрана —
  «История доставок и самовывозов».
- Одна карточка истории представляет целый маршрутный лист или целый документ
  самовывоза. Нажатие открывает этот документ полностью в существующем режиме
  просмотра. Карточки отдельных клиентов/покупок в общем списке не создаются.
- Единый поиск по имени клиента, адресу и телефону работает по всем совпадающим
  карточкам клиентов. Поиск отбирает документы, в которых встречается подходящий
  клиент; выбор одного `clientId` не ограничивает просмотр истории. Документ
  выводится один раз, даже если в нём несколько совпадающих клиентов.
- Сумма и количество клиентов/покупок в карточке относятся ко всему документу,
  включая записи, не совпавшие с текстом поиска. Поиск не пересчитывает эти итоги
  только по найденному клиенту.
- Диапазон дат фильтрует по плановой дате доставки/самовывоза (`plannedDate`).
  Он обязателен всегда, независимо от текста поиска и остальных фильтров.
  Поиск и диапазон действуют совместно; запрос истории без ограниченного
  периода не допускается.
- Выбор диапазона переиспользует `showAppDateRangePicker` из
  `lib/shared/utils/app_date_range_picker.dart` и существующий
  `AppDateRangeDialog`, как в журнале событий и отчёте продаж. Новый диалог
  календаря для истории не создаётся; изменение периода применяется после
  подтверждения существующего диалога.
- Отменённые документы по умолчанию скрыты. Для их включения используется
  существующий `LabeledCheckboxToggle` с подписью «Показывать отменённые».
  Этот же компонент уже используется для «Деактивированные» в списке клиентов
  и для отменённых документов в диалоге документов дня. Общий компонент менять
  ради нового экрана не требуется.
- Самовывозы без клиента входят в историю; модель клиентов не объединяется
  и не изменяется в рамках этого этапа.

## Согласованный состав карточки документа

- Для доставки: тип документа, плановая дата, водитель, машина, общая сумма
  маршрута и количество клиентов.
- Для самовывоза: тип документа, плановая дата, общая сумма и количество покупок.
  Поля водителя/машины отсутствуют.
- Если отменённые документы включены, их статус явно виден.
- Нажатие открывает соответствующий маршрут или самовывоз целиком.

При непустом поиске внутри карточки документа отображаются отдельные блоки
покупок совпавших клиентов: имя и данные для различения карточек клиента,
краткий состав товаров с количеством. По нажатию на блок открывается диалог
с полной покупкой этого клиента в данном документе: товарные строки,
количество, цена, сумма строки, итог и сохранённый способ оплаты.
Если совпали разные карточки клиентов с одним названием, их покупки не
смешиваются. Нажатие на блок покупки открывает только диалог, а на остальную
карточку — исходный документ. Общие итоги карточки остаются итогами документа.
При пустом текстовом поиске карточка показывает общий обзор документа.

В интерфейсе истории слово «точка» не используется: для доставки — «Клиент»,
для безымянного покупателя — «Клиент (анонимный)». В счётчике самовывоза
используется «Покупок». Это уточнение истории не переименовывает уже согласованную
кнопку «Добавить покупку» в конструкторе самовывоза.

## Период истории

По умолчанию — последние 30 календарных дней, включая сегодня:
от сегодняшней даты минус 29 дней до сегодняшней даты, с включением обеих границ.
Период явно виден на экране и продолжает действовать при поиске клиента.
Для более старой истории пользователь расширяет диапазон существующим диалогом.
«Сбросить фильтры» возвращает этот диапазон, очищает поиск и скрывает отменённые
документы. Очистка поиска или изменение других фильтров не снимает ограничение
по датам. В API обе границы периода обязательны.

Согласованный максимум — один год на запрос, чтобы была доступна годовая история
клиента. Ограничивается
длительность выбранного периода, а не давность данных: можно просматривать
старые годы отдельными диапазонами. Учесть високосные годы при определении границ.
Максимум проверяют и Flutter, и backend. Если общий диалог выбора дат потребуется
расширить, ограничение должно быть необязательным параметром только для истории,
не меняющим возможности журнала событий и отчёта продаж.

## Технические детали для проектирования

- Сортировка: плановая дата, время создания, ID по убыванию. Страница —
  25 документов, максимум 100 через API; следующие страницы — «Показать ещё».
- Поиск использовать по текущим данным связанных карточек клиентов, как в
  существующем справочнике. Старых снимков адреса/телефона модель не хранит.
- Для поиска безымянных покупателей нельзя выдумывать клиентские данные:
  при непустом поиске по имени/адресу/телефону анонимные покупки не имеют
  совпадений по этим полям. Самовывозы доступны в выбранном периоде без такого
  текстового ограничения.

## Направление реализации

Backend предоставляет список с пагинацией и совместными фильтрами; Flutter
использует существующие компоненты, репозитории и общий HTTP-клиент. История
читается из сохранённых документов; новый экран не изменяет продажи или клиентов.
Правила дат, поиска, отмены и перехода к документу должны совпадать в API и UI.

Источник общего плана: `client-features-discussion-2026-11.md`.

## Реализация и проверка

- Backend: новый GET `/protected/delivery-history`, одна SQL-выборка для
  страницы и общего количества, без изменения схемы БД.
- Flutter: новая вкладка, обязательный период, поиск с небольшой задержкой,
  отменённые, сброс, обновление и загрузка следующих страниц. Ответы устаревших
  запросов не заменяют результаты нового поиска.
- Карточка открывает существующий просмотр документа. Отдельный блок клиента
  открывает диалог с сохранёнными товарами, количеством, ценами, суммами
  и способом оплаты. Изменение документа обновляет историю и календарь.
- Переиспользованы `AppBaseCard`, `AppDialogCard`, `LabeledCheckboxToggle`,
  `AppSecondaryButton`, `AppIconButton`, `showAppDateRangePicker` /
  `AppDateRangeDialog`. Необязательный `maxRangeMonths` ограничивает только историю.
- Полный backend-прогон: 491 passed. Полный Flutter-прогон без `live_api`:
  413 passed, 5 skipped. Новые проверки охватывают фильтры, полные итоги,
  несколько совпавших клиентов, анонимные покупки, пагинацию, исторические
  товары/оплату, високосные даты, устаревшие ответы и отдельное нажатие покупки.
- Flutter analyze и Ruff изменённых файлов проходят. Pyright изменённых файлов
  проходит; общая строгая проверка проекта сообщает 106 ошибок в остальных файлах.
