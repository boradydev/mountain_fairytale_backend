# Резервное копирование Hyper-V

- Виртуальная машина: `ubuntu_server`.
- Папка для копий: `E:\vm_backup\mountain_fairytale` (создаётся автоматически).
- Запуск: через 5 минут после загрузки Windows, от имени `SYSTEM` с наивысшими правами.
- Экспорт выполняется, только если с последней успешной копии прошло не менее 7 дней.
- Хранятся 3 завершённые копии этой VM. Старые удаляются только после успешного создания новой.
- При ошибке Планировщик заданий выполняет до 3 повторных попыток с интервалом 30 минут.
- Для работающей VM используется режим `CaptureCrashConsistentState`; выключенную VM также можно экспортировать.

## Режим горячего экспорта

По умолчанию используется `CaptureCrashConsistentState`: снимок дисков без
сохранения оперативной памяти и без запроса заморозки файловой системы внутри Ubuntu.
При восстановлении PostgreSQL выполняет восстановление по WAL, как после внезапной
остановки. Для этого в согласованный снимок должны попасть все файлы БД, включая WAL
и табличные пространства. В этой VM они находятся на одном виртуальном диске.
Записи после момента снимка в копию не входят; незавершённые транзакции не сохраняются
как подтверждённые. Это не гарантия согласованности с внешними сервисами или файлами
за пределами снимка.

Режим `CaptureDataConsistentState` можно выбрать параметром скрипта
`-CaptureLiveState CaptureDataConsistentState`. Он использует производственные
контрольные точки и требует исправной интеграции резервного копирования с гостевой
ОС. Ошибка «Не удается создать контрольную точку со сведениями о приложениях»
означает сбой этого этапа; сама по себе она не указывает точную причину. Для Ubuntu
следует проверить службу интеграции резервного копирования Hyper-V и гостевой
процесс `hv_vss_daemon`. Автоматического переключения между режимами нет.

Обновлённый XML явно задаёт `CaptureCrashConsistentState`. В ранее импортированном
задании без этого параметра будет использовано новое значение по умолчанию скрипта.

## Импорт задания

1. Откройте Планировщик заданий от имени администратора.
2. Выберите **Импортировать задачу** и укажите файл `hyperv-weekly-backup.xml` из этой папки.
3. Сохраните задание, например под именем `Еженедельная копия Hyper-V ubuntu_server`.
4. Для создания первой копии выберите задание и нажмите **Выполнить**.

В XML указан текущий абсолютный путь к скрипту:
`C:\Users\alexv\PycharmProjects\mountain_fairytale_backend\scripts\backup\export-hyperv.ps1`.
Если скрипт перемещён, обновите путь в действии задания. HDD должен быть доступен
учётной записи `SYSTEM` как диск `E:` и разблокирован, если используется шифрование.

Задание проверяет срок последней копии при загрузке ПК. Если компьютер работает
несколько недель без перезагрузки, следующая копия будет создана только при новой
загрузке или ручном запуске задания.

## Результаты работы

Результаты записываются в `E:\vm_backup\mountain_fairytale\backup.log`.
Код завершения задания `0` означает успешный экспорт или пропуск, если 7 дней ещё
не прошло; `1` означает ошибку. Папки завершённых копий содержат файл
`ExportCompleted.json` и папку экспортированной VM. В названия входят
идентификатор VM, дата и время, а также случайный суффикс.

Незавершённые экспорты сохраняют суффикс `.partial` и не учитываются в числе трёх
хранимых копий. Они занимают место: их следует проверить и при необходимости
удалить вручную. На время нового экспорта должно хватать места для четвёртой
полной копии; старые завершённые копии удаляются после его успешного окончания.
Существующие экспорты без файла-маркера этого скрипта не удаляются и не учитываются
при проверке срока последней копии.

Успешное завершение экспорта само по себе не подтверждает возможность
восстановления. Прежде чем полагаться на расписание, проверьте импорт и запуск
копии в отдельной VM, изолированной от рабочей сети.
